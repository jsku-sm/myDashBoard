## 2. GitHub 저장소는 두 개로 나누세요

**코드 저장소** 예: `gussaem-classroom-app`

지금 받은 코드 파일을 넣는 저장소입니다. 실제 학생 정보나 키를 넣지 않는다면 공개 또는 비공개로 선택할 수 있습니다. Streamlit 배포는 이 저장소에 연결합니다.

**데이터 저장소** 예: `gussaem-classroom-data`

반드시 **Private**로 생성하세요. 학생 계정, 감정·로그인 기록, 과제, 수다노트와 첨부파일은 여기에 암호화해 저장합니다. 생성할 때 **Add a README file**을 켜서 `main` 브랜치를 만드세요. 이 저장소에는 앱 코드를 따로 올릴 필요가 없습니다.

두 저장소 모두 GitHub입니다. Firebase·Supabase나 별도 데이터베이스 프로그램은 사용하지 않습니다. 데이터 변경이 앱 코드 변경과 섞이지 않도록 저장소를 분리하는 구성입니다.

학생에게 데이터 저장소 접근 권한, GitHub 토큰, 암호화키를 주지 마세요.

## 4. GitHub 토큰 만들기

GitHub 프로필 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token** 순서로 들어갑니다.

- Resource owner: 데이터 저장소 소유자
- Repository access: **Only select repositories**에서 데이터 저장소 한 개만 선택
- Repository permissions → **Contents: Read and write**
- Metadata: 기본 읽기 권한
- 만료일은 운영 기간과 관리 기준에 맞게 설정하고, 만료 전에 갱신하세요.

발급한 토큰은 Streamlit Secrets에만 입력합니다. 채팅, 코드, 학생 계정표, GitHub README에 쓰지 마세요. 토큰 문자열은 발급 화면을 닫으면 다시 볼 수 없으므로 안전하게 보관하세요.

## 5. Streamlit에 배포하고 Secrets 입력

Streamlit Community Cloud에서 **Create app**을 선택하고 코드 저장소를 연결합니다.

```text
Repository: 내아이디/gussaem-classroom-app
Branch: main
Main file path: app.py
Python: 3.12
```

처음에는 Secrets 없이 배포해도 됩니다. 앱에 표시되는 초기 설정 화면에서 **설정용 새 암호화키 만들기** 버튼을 누르고 키를 복사하세요. 터미널을 사용할 수 있다면 `python scripts/make_key.py`로 생성해도 됩니다.

배포 앱의 **Settings → Secrets**에 아래를 붙여 넣고 실제 값으로 바꿉니다.

```toml
STORAGE_MODE = "github"
GITHUB_REPO = "내아이디/gussaem-classroom-data"
GITHUB_BRANCH = "main"
GITHUB_TOKEN = "발급한_토큰"
ENCRYPTION_KEY = "방금_생성한_암호화키"
TEACHER_ID = "teacher"
TEACHER_INITIAL_PASSWORD = "본인이_정한_12자이상_비밀번호"
```

저장하고 앱이 다시 시작되면 교사 아이디와 비밀번호로 로그인합니다. `TEACHER_INITIAL_PASSWORD`는 데이터 저장소에 계정이 없을 때 한 번만 사용됩니다. 앱에서 비밀번호를 변경한 후에는 새 비밀번호가 적용되며, Secrets의 초기값으로 자동 초기화되지 않습니다.

**암호화키는 비밀번호 관리 도구 등 안전한 별도 장소에도 보관하세요.** 기존 학생 데이터가 있는 상태에서 키를 새로 만들거나 바꾸면 기존 데이터를 읽을 수 없습니다. 키를 잃어버렸을 때 복구하는 우회 기능은 없습니다.

## 6. 학생 명렬 등록

교사 로그인 → **학생 관리 → CSV 명렬 일괄 등록**에서 명렬을 업로드합니다.

첫 행은 `학번,이름,학급`입니다. 학번은 4~12자리 숫자이며, 학급은 `1-1`부터 `1-7`까지입니다. 추가 열이 있어도 필요한 세 열만 읽습니다. UTF-8 또는 CP949 CSV를 받습니다.

```csv
학번,이름,학급
1101,학생이름,1-1
1102,학생이름,1-1
1201,학생이름,1-2
```

파일에 포함된 예시 이름은 가상이므로 실제 명렬로 교체하세요. 학생마다 서로 다른 임시 비밀번호를 자동 발급합니다. 발급표를 내려받아 학생 본인에게 개별 전달하고, **발급표를 화면과 세션에서 지우기**를 누르세요. 내려받은 임시 계정표는 배부 후 안전하게 삭제하세요.

학생은 최초 로그인 후 비밀번호부터 변경하고 다시 로그인합니다. 현재 비밀번호는 원문으로 보관하지 않으므로 교사도 조회할 수 없습니다. 잊어버리면 해당 학생만 초기화합니다. 초기화 또는 계정 중지 후 기존 세션은 다음 권한 확인 때 만료됩니다.

## 7. 첫 수업 운영 순서

1. **교실 설정**에서 자기소개·관심 분야·단원·도구 주소를 확인합니다.
2. 과목 메뉴에서 **평가계획·학습지·수업자료 올리기**로 자료를 등록합니다.
3. **학생 제출 과제 만들기**에서 단원과 대상 학급을 정합니다. 일반 제출 과제는 공유 체크를 끕니다.
4. 학생은 로그인 → 임시 비밀번호 변경 → 재로그인 → 감정 선택 → 과목 자료 확인 → 과제 제출 순서로 사용합니다.
5. 교사는 **교사 대시보드**에서 접속·감정 현황을 확인하고, 설명할 때 해당 학급의 화면을 잠급니다.
6. 수업 후 학생은 **수다노트**를 작성합니다. 교사는 학생별 기록과 과제를 보며 개별 피드백·관찰기록을 남깁니다.
7. **좌석배치표**에서 배치 후 저장하고, 준비가 끝나면 해당 학급 학생 공개를 켭니다.

학생끼리 공유하는 과제라도 **개별 자동 피드백·교사 피드백은 본인·교사만 볼 수 있습니다.** 공개 질문의 교사 답변은 질문과 같은 범위로 공개됩니다.

## 8. 자동 피드백은 어떻게 작동하나요?

### 기본값: API 없이 제출 확인

제출 즉시 앱에 접수 메시지와 과제에 미리 적은 교사 공통 안내가 표시되고, 제출 기록에 저장됩니다. 교사는 나중에 학생별 피드백을 추가할 수 있습니다. 자동 피드백은 외부 문자·이메일이 아니라 **앱 안의 메시지**입니다.

PDF·사진·한글 파일의 답안 내용을 자동으로 읽거나 채점하지 않습니다. 파일만 제출한 경우에도 파일을 분석한 것처럼 말하지 않습니다.

### 선택값: 직접 입력한 설명에 AI 피드백

Secrets에 아래 값을 추가한 다음, 교실 설정에서 AI 사용을 켭니다. 모델 이름은 해당 API 계정에서 이용 가능한 모델을 입력하세요. 모델을 임의로 고정하거나 무료라고 가정하지 않습니다.

```toml
OPENAI_API_KEY = "발급한_API_키"
OPENAI_MODEL = "계정에서_사용_가능한_모델명"
```

각 제출 화면에서 학생이 선택 동의한 경우에만 직접 입력한 풀이·생각·수다노트 텍스트를 전송합니다. 파일, 명렬, 감정, 관찰기록은 전송하지 않습니다. 개인정보 패턴 일부를 제거하지만 완전한 익명화를 보장하지 않으므로 이름·연락처를 적지 않게 지도하세요. 학교의 외부 AI 이용 기준과 학생 관련 절차를 먼저 확인하세요.

응답은 **AI 학습 피드백 · 교사 확인 전**으로 표시됩니다. 모델·네트워크·비용 한도 문제가 발생하면 제출 확인으로 대체합니다. AI가 성적을 산정하지 않습니다. 실제 API 연결은 이 제작 환경에서 실행 검증하지 않았습니다.

## 9. 화면 잠금과 접속 상태의 정확한 범위

**잠글 수 있는 범위:** 이 Streamlit 앱 안의 일반 클릭·키보드 조작과 새로운 저장·파일 준비 요청입니다. 학급별 또는 전체로 지정합니다. 학생 화면은 약 3초 간격으로 확인하므로 네트워크·서버 지연이 추가될 수 있습니다. 전체 잠금이 켜져 있으면 학급별 해제보다 우선합니다.

잠금 상태는 독립된 화면 부분에서 확인하므로, 정상적인 잠금·해제 과정에서 학생이 작성 중인 입력 영역을 다시 만들지 않습니다. 브라우저 구성요소 테스트에서 잠금 중 입력 차단, 기존 입력 유지, 해제 후 입력 재개를 확인했습니다. 다만 **새로고침, 브라우저 종료, 앱 재시작으로 아직 제출하지 않은 입력까지 복구하는 기능은 아닙니다.**

**잠글 수 없는 범위:** 이미 열린 외부 도구 탭, 다른 앱, 아이패드 전체, 운영체제, 이미 내려받은 파일과 이미 브라우저에 전달된 다운로드 주소입니다. 브라우저 개발자도구로 화면을 변조하려는 사용자를 통제하는 시험용 보안 브라우저도 아닙니다. 잠금만으로 감독·부정행위 방지를 보장하지 않습니다.

현재 접속은 같은 서버에서 최근 20초 내 신호가 확인된 상태입니다. 하루 로그인 기록은 GitHub에 남지만, 순간 접속 정보는 서버 메모리에만 있습니다. 절전·네트워크 중단·서버 재시작 시 정확한 현재 접속과 차이가 생깁니다. **로그인 통계를 출석 확정 자료로 대신 사용하지 마세요.**

상점은 접속 중인 해당 학생 화면에 폭죽과 알림을 표시합니다. 기기에서 동작 줄이기를 켠 경우 알림만 표시합니다. 미접속 중 부여한 상점·벌점은 다음 로그인 후 누적 기록에서 확인합니다.

```text
classes/1-2/... ~ classes/1-7/...
students/무작위학생ID/notes.enc         해당 학생의 누적 수다노트
students/무작위학생ID/profile.enc       개인 소개·관심 분야
files/무작위파일ID.enc                  암호화된 실제 첨부파일
```

`.enc`는 암호화 파일이므로 GitHub 웹페이지에서 바로 읽는 표가 아닙니다. **앱의 교사 메뉴와 CSV 내려받기**로 내용을 확인합니다. 학생별 무작위 ID와 학번의 관계는 계정 파일에 저장됩니다. 암호화 내부 데이터는 JSON이며, 별도 데이터베이스가 아닙니다.

비밀번호는 무작위 salt를 사용하는 PBKDF2-SHA256 600,000회 해시로 저장하고, 그 해시가 든 계정 파일도 Fernet으로 암호화합니다. 같은 비밀번호를 쓰더라도 운영 계정의 salt는 다릅니다.

## 11. 운영 전에 알아둘 제한

**파일당 8MB**입니다. PDF, PNG, JPG, JPEG, WEBP, TXT, MD, DOCX, PPTX, XLSX, HWP, HWPX를 받습니다. 위험한 실행 파일·HTML은 허용하지 않습니다. 업로드 파일 자체를 백신 검사하는 기능은 없고, 서버에서 첨부파일 코드를 실행하지 않습니다.

GitHub는 실시간 데이터베이스가 아니며 API 읽기·쓰기 제한이 있습니다. 같은 앱 서버의 학생들은 잠금 확인 캐시를 공유하고, 심박 신호를 GitHub에 쓰지 않도록 했습니다. 파일 저장 요청은 순차화하고 SHA 충돌이 생기면 최신 내용을 읽어 재시도합니다. 요청 제한·네트워크 오류가 있으면 실패를 표시하고, 로컬 임시 저장으로 성공한 척하지 않습니다.

**25명 동시 저장 테스트는 로컬 파일 저장 계층에서 수행했습니다. 실제 GitHub 연결 상태의 25명 동시 접속·업로드 부하 시험은 수행하지 않았습니다.** 배포 후 먼저 교사와 학생 가상 계정 2~3개로 시험하고, 실제 수업 전 해당 학급 기기로 점검하세요. 여러 서버 인스턴스 사이의 실시간 접속 통계 공유는 지원하지 않습니다.

GitHub는 변경 이력을 보관합니다. 앱에서 자료를 보관하거나 파일을 지운다고 과거 커밋까지 사라지는 것은 아닙니다. 학생 자료의 보관 기간과 이력 정리 절차를 학교 기준에 맞게 정하고, 암호화키와 백업 접근 권한도 함께 관리하세요. 자동 영구 삭제 기능은 넣지 않았습니다.

자료 파일 저장 후 목록 저장이 실패하면 목록에 연결되지 않은 암호화 첨부가 남을 수 있습니다. 같은 제출 화면의 재시도는 요청 번호로 중복을 줄이지만, 서로 다른 파일과 목록을 한 번에 저장하는 데이터베이스 트랜잭션은 아닙니다. 실패 시 원본 파일과 입력 내용을 보관하고 등록 여부를 먼저 확인하세요.

## 12. 내 컴퓨터에서 실행

Python 3.12 환경에서 다음을 실행합니다. 이 수정본은 로컬 실행에서도 GitHub에 저장합니다.

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Mac에서 `python` 대신 `python3`가 필요할 수 있습니다.
`.streamlit/secrets.toml.example`을 `.streamlit/secrets.toml`로 복사해 실제 값을 입력하세요.
실제 `secrets.toml`은 GitHub에 올리지 않습니다. Secrets가 없으면 초기 설정 화면만 표시됩니다.
로컬 데모 계정은 만들지 않으며, GitHub 연결 실패 시 로컬 파일로 자동 대체하지 않습니다.

## 13. 오류가 났을 때

| 표시 내용 | 확인할 것 |
|---|---|
| `No module named ...` | 폴더 전체 업로드 여부, requirements.txt 설치, Main file path |
| 아직 Secrets가 없음 | 앱 Settings → Secrets에 실제 운영값 저장 |
| 데이터 저장소를 찾을 수 없음 | `아이디/저장소명`, Private 저장소 선택 범위, 토큰 만료일 |
| 브랜치가 없음 | 데이터 저장소 생성 시 README 추가, `main` 존재 여부 |
| 쓰기 권한 문제 | Contents Read and write, 브랜치 보호 규칙·조직 정책 |
| 암호화키가 기존 데이터와 다름 | 최초에 사용한 ENCRYPTION_KEY 복구. 새 키로 덮어쓰지 않기 |
| 저장 요청 제한 | 업로드·조회 횟수 줄이기, GitHub 한도·오류 확인 후 재시도 |
| 비밀번호를 잊음 | 교사: 학생 관리 → 선택 학생 비밀번호 초기화 |
| 학생 기기에서 잠금 확인이 늦음 | 네트워크·브라우저 절전 확인. 약 3초 확인 주기 외 지연 가능 |
